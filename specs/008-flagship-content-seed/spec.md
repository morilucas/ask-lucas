# Feature 008: flagship portfolio content seed

Status: Approved for implementation
Date: 2026-08-02

## Intent

Replace the LinkedIn-level summary of Lucas's current work with an initial set of evidence-rich,
employer-facing case studies. The seed should demonstrate ownership of data products, large-scale
data engineering, cross-functional delivery, and evaluated AI systems while preserving a deliberate
public-content boundary.

## Source and approval boundary

- Inputs are Lucas-authored FY2025 and H1 2026 performance summaries plus his explicit review in the
  project conversation.
- The raw summaries and underlying employer documents never enter either repository or the retrieval
  index.
- Lucas approved the real internal project and tool names and the latest H1 2026 aggregate numbers
  on 2026-08-02.
- Every numerical claim records its time period, definition, and measured or estimated status in a
  private claim ledger.
- Customer-specific outcomes, colleague names, raw document links, tables, fields, code, prompts,
  access-control mechanics, and internal performance ratings remain excluded.

## Initial content scope

1. Share of Voice (SOV) 2.0: self-initiated product development, permission-aware productization,
   global adoption, collaboration features, and qualified aggregate impact.
2. Brand Basics: progression to main data ownership, pipeline and dashboard modernization,
   cross-functional metric design, regional expansion, and analytical proof points.
3. Ads Lite: end-to-end dataset creation, scale-driven re-architecture, time-zone fidelity,
   performance, historical depth, and managed migration.
4. Brand Basics Q&A assistant: prototype status, layered knowledge design, explicit evaluation set,
   iteration, and bounded internal evaluation results.

## Content requirements

- Each project is one independently retrievable level-two Markdown section with a stable source ID.
- State what Lucas personally owned and distinguish inherited, collaborative, and self-initiated work.
- Use the latest H1 2026 number when an older and newer number measure the same thing.
- Keep different measurements separate rather than combining them; estimated values must say how
  they were estimated.
- Label prototype, research, and production status accurately.
- Write in third person and attach no claims that the approved inputs do not support.

## Evaluation requirements

Add private employer questions that verify retrieval and answer behavior for each new source. Include
at least one question that requires the assistant to distinguish an estimate from a measured value
and one that requires it to identify prototype status without claiming production deployment.

## Acceptance

- The private content validator accepts every new section and reports no duplicate source IDs.
- The index rebuild succeeds and produces the same corpus fingerprint as validation.
- Existing privacy, unsupported, and prompt-injection evaluations remain present.
- No raw performance review, internal document, customer-level result, colleague name, or prohibited
  implementation detail enters either repository.
